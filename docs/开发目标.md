### 安全功能

**机器 A（云服务器）：搞定证书与转发**

- [ ] **配真证书**：给域名申请正式 SSL 证书（别用自签名，GitHub Pages 会拦截）。

- [ ] **调 Nginx**：
  
  - [ ] 开启 **HTTPS (443)** 访问。
  
  - [ ] 配置 **WSS 转发**（允许协议升级 `Upgrade`）。
  
  - [ ] 允许 **跨域 (CORS)**（放行 `github.io` 的请求）。

**2. 机器 B（内网受控端）：搞定主动连接**

- [ ] **写主动连接**：Agent 代码里设置为启动后**主动连接**机器 A 的 WSS 地址。

- [ ] **省去内网穿透**：确认 Agent 能正常上网即可，**无需配置 Frp** 或端口映射。

- [ ] **加自动重连**：确保网络波动断开后，Agent 能每隔几秒自动连回后端。

**3. 前端（GitHub Pages）：更新地址**

- [ ] **改请求路径**：把代码里的 API 和 WebSocket 地址全部换成机器 A 的 **HTTPS/WSS** 开头的域名。

**3. 安全测试**

- [ ] **非法调用测试**：用 Postman 模拟黑客，看没 Token 能不能远程把服务器关了。

- [ ] **输入防御测试**：输入各种特殊符号（`; & |`），看 Agent 会不会“听话”地执行多条指令。

- [ ] **证书失效测试**：故意把后端时间调乱让证书过期，看前端能不能感知到风险。

- [ ] **XSS 注入测试**：在插件名称、配置描述中输入 HTML 标签，看网页是否崩溃或弹窗。

- [ ] **权限边界测试**：手动修改前端本地存储的 `role` 字段，看是否能绕过界面限制调接口。

- [ ] **错误处理测试**：故意发错格式的请求，看后端返回的是“友好提示”还是“系统内部细节”。

- [ ] **重放攻击测试**：抓取一个一小时前的安装指令包再次发送，看后端是否因为 Token 过期而拒绝。
